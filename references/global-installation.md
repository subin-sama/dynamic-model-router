# Global installation adapters

The one-command installer configures **user-wide routing instructions**, not a background daemon or a forced model switch. It writes a managed English block containing the selected installed `SKILL.md` path and asks the agent to apply that policy to every task. The user's surrounding instructions remain untouched, whatever language they use.

The managed block also requests a compact Markdown blockquote at task start and meaningful changes or outcomes: a bold Routing/status line with a colored emoji, a scope/model/effort line, and an optional short reason. Status, scope, labels, and reason follow the user's language; model IDs and native effort values stay exact. Indicators supplement the textual labels: 🟦 recommended, 🟨 requested, 🟪 applied, 🟩 verified, ⚪ unchanged, 🟧 unverified, and 🟥 error. Text-only fallback remains available. Host styling and emoji rendering determine the appearance; setup does not inject CSS or animate the chat. Plain-text hosts use a compact line. Terminal receipts and structured records retain their existing format. It distinguishes recommendations, requests, acknowledgements, runtime verification, and unknown or inherited settings. This summary prefers the chat format and indicators over old raw-log or neutral-icon examples when a manual legacy skill is reused. Updating an older installer-owned block replaces only that block; unowned legacy instructions are preserved. Chat receipts are generated by the assistant and do not install native app banners or guarantee every host event is logged.

When the host exposes a supported native surface, the managed block prefers [native inline receipts](inline-receipts.md). Installer-owned copies include the HTML template and optional Python renderer. CSS and animation run only inside that native sandbox, without modifying the host application. Codex's final-response-only visualization contract retains an initial text receipt; Antigravity App publishes a native user-facing HTML artifact. Reused manual copies are preserved, so a missing rich-renderer payload falls back to text rather than being overwritten or silently claimed as installed.

## Targets

| Agent ID | Instruction root and file | Skill candidates |
| --- | --- | --- |
| `codex` | `CODEX_HOME` or `~/.codex`; effective `AGENTS.override.md` when nonempty, otherwise `AGENTS.md` | Shared `~/.agents/skills/dynamic-model-router`, or an existing Codex-home `skills/dynamic-model-router` |
| `claude-code` | `CLAUDE_CONFIG_DIR` or `~/.claude`; `CLAUDE.md` | Config-root `skills/dynamic-model-router`, with an existing shared copy reusable |
| `gemini-cli` | `GEMINI_CLI_HOME` or the OS home, then `.gemini`; configured global context filename or `GEMINI.md` | The same home root's `.agents/skills/dynamic-model-router` or `.gemini/skills/dynamic-model-router` |
| `antigravity` | OS home, then `.gemini/AGENTS.md` | Shared across Antigravity App, CLI, and IDE: `.gemini/config/skills/dynamic-model-router` |
| `opencode` | `OPENCODE_CONFIG_DIR`, otherwise `XDG_CONFIG_HOME/opencode` or `~/.config/opencode`; `AGENTS.md` | Shared or native config-root `skills/dynamic-model-router` |
| `github-copilot` | `COPILOT_HOME` or `~/.copilot`; `copilot-instructions.md` | Shared or config-root `skills/dynamic-model-router` |

`GEMINI_CLI_HOME` replaces the home root; the installer appends `.gemini`. `CLAUDE_CONFIG_DIR`, `COPILOT_HOME`, and `CODEX_HOME` identify their configuration directories directly. The installer reads existing environment overrides without changing them.

Gemini settings support comments. The adapter reads system-default, user, and system settings to honor `context.fileName`, including safe filename arrays. It does not evaluate JavaScript, accept trailing commas, or change administrator settings. Future workspace settings and Gemini's own trust/security decisions can still affect what it loads.

OpenCode configuration-directory behavior is version-sensitive. The installer reports the actual target it chose. Applicable project instructions can override user-wide guidance across hosts; managed policies and explicit user choices remain authoritative.

## Antigravity

The Antigravity adapter uses `~/.gemini/AGENTS.md` for always-active global instructions and `~/.gemini/config/skills/dynamic-model-router` for a skill shared by App, CLI, and IDE. It is separate from the Gemini CLI adapter. No Antigravity customization-home environment override is assumed; `GEMINI_CLI_HOME` applies only to Gemini CLI in this installer.

Antigravity CLI gives same-name skills in `~/.gemini/antigravity-cli/skills/` and `~/.gemini/skills/` priority over the shared configuration skill. The App does not read those CLI-only locations. The IDE also supports legacy skills under `~/.gemini/antigravity/skills/`.

Before writing, setup checks for a `dynamic-model-router` copy in each of those locations. A competing copy blocks setup unless it resolves to the selected skill or is installer-owned and updated in the same installation plan. This permits a current managed Gemini CLI copy during `--agents all`, while preventing an unresolved manual or stale copy from silently winning discovery. A conflict reports its path; review or relocate that copy before retrying.

Detection uses the `agy` or legacy `antigravity` executable, or Antigravity-specific configuration directories. The presence of a generic `~/.gemini` folder alone does not identify an Antigravity installation. Detection and file installation do not prove that the running agent loaded the policy or can switch its own model.

## Selection and inspection

With no options, setup targets detected supported agents. Configuration-directory presence or a corresponding executable is a detection signal, not proof of a tested runtime version. `--agents all` explicitly configures all six adapters. Unsupported IDs fail without partial setup.

```bash
npx --yes github:subin-sama/dynamic-model-router --agents codex,gemini-cli --dry-run
npx --yes github:subin-sama/dynamic-model-router --agents all --json
```

`--home PATH` is an isolated staging mode. It ignores real profile environment overrides and is useful for installation testing without changing the actual user's home. It does not rewrite `HOME` or `CODEX_HOME`.

## Unsupported automatic activation

Cursor can discover skill files, but its dependable all-project User Rules mechanism is account/UI-backed and file-backed global rules have version limitations. This installer does not modify private application databases or claim that copying a skill enables all-project Cursor activation.

Hosted ChatGPT/Claude web or mobile products and arbitrary closed AI applications do not share these local instruction paths. Use their supported custom-instruction, plugin, or agent integration. A universal policy format does not imply a universal installation hook.

## Preservation and removal

Setup prepares all selected changes before writing, backs up changed instruction files, and maintains a uniquely marked routing block. Repeating setup updates only that block. Malformed markers and detected conflicting edits stop installation. Backups are recovery copies, not files automatically restored over future user work.

Uninstall removes only recorded managed activation and unchanged installer-owned payload files. Modified files, user additions, manual installations, and shared payloads still referenced by other configured agents are preserved.
